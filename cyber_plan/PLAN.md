# سايبر نت — شبكة رقمية بهوية مشفرة (CyberNet)
## وثيقة التنفيذ المرجعية — نظام "المشترك الرقمي" فوق شبكات المضيفين

> **الحالة:** تخطيط مؤكد — التجربة الميدانية: المعلا/عدن (نطاق: شارع واحد عند مضيف مؤسس)
> **أُنشئت:** 2026-11-02 · **النطاق:** `testapp` + مكونات خادم مستقلة — عزل تام عن `acc_*` و`mikrotik_*` وكل النواة
> **الرموز:** ⬜ لم تبدأ | 🔶 قيد التنفيذ | 🧪 باختبار | ✅ منجزة | ⏸️ مؤجلة

## 1) الفكرة بجملة واحدة

شبكة "اتصالات افتراضية" فوق راوترات MikroTik المنتشرة: العميل يثبّت تطبيق «سايبر نت» مرة واحدة، يحصل على **رقم شريحة رقمية من 9 خانات يبدأ بـ 74** وشهادة مشفرة في جهازه، ثم يتصل جواله **تلقائياً وبصمت** بأي شبكة `CyberNet` في أي حي — بلا صفحة دخول، بلا كروت، بلا كلمات مرور. الشحن برقم الشريحة عبر وكلاء (بقالات) بإشعار فوري، والفوترة والباقات وقطع الخدمة تدار كلها مركزياً من خادمنا.

## 2) لماذا لا يُقلَّد (سرّ المهنة)

| الطبقة | مالكها | ما يمنع النسخ |
|---|---|---|
| شهادات EAP-TLS + CA خاص | سيرفرنا فقط | لا أحد يولّد اشتراكاً صالحاً دون مفتاح CA — حتى لو نُسخت إعدادات الراوتر |
| محرك الفوترة والباقات والأرصدة | باكند `testapp` | المضيف لا يرى أسعاراً ولا أرصدة — يرى حصته فقط |
| تطبيق العميل + ملف تعريف الواي فاي | نحن | تجربة "شركة الاتصالات" تعيش في التطبيق، لا في الراوتر |
| ملف `.rsc` المعتم | يُسلَّم للمضيف | سطران: SSID + خادم وسرّ — لا منطق، لا باقات، لا شيء يُفهم |

**قاعدة ذهبية:** المضيف = هوائي أعمى. العقل كله على سيرفرنا.

## 3) المعمارية

```
جوال العميل (شهادة EAP-TLS + رقم 74XXXXXXXX)
      │  WPA2-Enterprise تلقائي — بلا صفحة دخول
      ▼
MikroTik المضيف: SSID "CyberNet" → RADIUS عبر WireGuard
      │  Access-Request / Accounting (UDP 1812/1813) + CoA (3799)
      ▼
سيرفر سايبر (VPS): FreeRADIUS ←→ محرك الفوترة
      │  HTTPS API
      ▼
باكند testapp (الاستضافة الحالية): حسابات، أرصدة، باقات، تسويات، إشعارات FCM
```

- **تفويض كل اتصال** يرجع من RADIUS: `Mikrotik-Rate-Limit` (السرعة) + `Session-Timeout` + حد البيانات.
- **محاسبة حية** كل دقائق: `NAS-Identifier` = هوية المضيف — كل جيجا موسومة بمضيفها.
- **قطع لحظي**: نفاد الباقة/الرصيد ← CoA Disconnect.

## 4) نموذج التسجيل والاشتراك (مواصفات مؤكدة من المالك)

### 4.1 تسجيل العميل (أول مرة — للحصول على رقم الشريحة)
| الحقل | القاعدة |
|---|---|
| الاسم الكامل | **رباعي كحد أدنى** — يقبل أكثر، يرفض أقل (تحقق بالكلمات ≥ 4) |
| الهوية | صورة البطاقة الشخصية وجهتين **أو** صورة جواز السفر |
| المحافظة | قائمة اختيار |
| المديرية | قائمة اختيار مرتبطة بالمحافظة |
| الناتج | رقم شريحة **9 خانات يبدأ بـ 74** (`74XXXXXXX`) — فريد، دائم، هو هوية المشترك |

### 4.2 الشحن والباقات (تجربة المعلا)
- **الشحن**: وكيل البقالة (تطبيقه الخاص) يدخل رقم الشريحة + المبلغ ← رصيد العميل يزيد لحظياً ← **إشعار فوري للعميل**: «تم شحن رصيدك».
- **باقات التجربة**: يوم 200 ريال — أسبوع 800 ريال — شهر 1,500 ريال، ولكل باقة عدد جيجات محدد (تُضبط في لوحة الإدارة قبل الإطلاق).
- الباقة تُفعَّل من التطبيق بزر واحد؛ تنفذ الجيجات أو المدة ← تنقطع تلقائياً حتى شحن جديد.

### 4.3 التجربة اليومية
- المستخدم يشغّل WiFi فقط ← الجهاز يمسك أي إشارة `CyberNet` (حتى ضعيفة) ويتصل ويصادق بصمت — **لا يُطلب منه أي إجراء مرة أخرى**.

## 5) تسوية أرباح المضيفين

- كل جيجا تُقدَّم تُحسب بقيمتها وتوزع: **حصة المضيف 65–70%** (قابلة للضبط) + حصة المنصة.
- التجوال بين المضيفين عادل تلقائياً: كل مضيف يُدفع له عن ما مرّ عبر راوتره.
- منع التلاعب: تقاطع عدّادات RADIUS مع عدّادات الراوتر عبر API؛ شذوذ = تنبيه.
- المضيف يرى في لوحته: جيجا اليوم + مستحقاته فقط. يُصرف أسبوعياً/حسب الطلب.

## 6) عقد العزل والتوازي (إلزامي)

### 6.1 نطاق الملكية — Track CYB
| المكوّن | المسار المملوك |
|---|---|
| جداول | `cyber_*` فقط — ممنوع `acc_*`/`mikrotik_*`/جداول النواة |
| باكند | `app/Http/Controllers/Api/Cyber/**`, `app/Models/Cyber*`, `app/Services/Cyber*`, `routes/api_cyber.php`, `app/Providers/CyberServiceProvider.php` |
| تطبيق العميل | تطبيق Flutter مستقل `cyber_client_app/` (أو `features/cyber/**` إذا قُرّر الدمج لاحقاً) |
| تطبيق الوكيل | شاشات `cyber` داخل تطبيق الوكيل/البقالة القائم خلف FeatureGate |
| سيرفر RADIUS | مستقل على VPS — `cyber-radius/` مجلد أدوات مستقل في المستودع (Docker) |
| ملفات المضيفين | `cyber-radius/host-templates/*.rsc` — قوالب معتمة تُولَّد لكل مضيف |

### 6.2 الملفات المشتركة — تُجمَّد بعد لمسة واحدة
`bootstrap/providers.php` (تسجيل CyberServiceProvider) · `pubspec.yaml` اعتماديات العميل · مفاتيح ميزات `cyber.*`.

### 6.3 قواعد ذهبية
1. Migrations **additive فقط**؛ كل `cyber_*` مرتبط بـ `network_owner_id` حيث يلزم.
2. صفر مساس بـ: auth, wallets, acc_*, mikrotik_*, transactions, cards — قراءة فقط إن لزم الربط.
3. كل ميزة خلف `FeatureGate('cyber.*')` — `enforce=0` أثناء التطوير.
4. Clean code + بنية قابلة للتوسع (مضيفون، باقات، أجهزة لاحقة) — لا منطق في الكنترولرز، كلها في Services.
5. كل مهمة: `flutter analyze` نظيف + PHPUnit للمسارات + اختبار ADB live موثّق.
6. أي تعارض مع ملفات مسار آخر ← إيقاف فوري + رسالة في صندوق shared.

## 7) متطلبات الخوادم

| المكوّن | المكان | الحد الأدنى |
|---|---|---|
| باكند testapp (الحالي) | Hostinger Cloud Startup — **يبقى كما هو** | — |
| FreeRADIUS + محرك سايبر + WireGuard | **VPS إلزامي** (منافذ UDP 1812/1813/3799 + root) | 1vCPU/2GB/Ubuntu 24.04 — ~$4.5–6/شهر |

> Cloud Startup **لا يمكنها** استضافة RADIUS (استضافة مدارة: لا root ولا UDP مخصصة). الباكند يبقى عليها؛ RADIUS على VPS فقط.

# ملحق سري — أدلة الفحص الخام (لصاحب الشبكة فقط)

**سري للغاية — لا يُشارك خارج مالك الشبكة.** هذا الملحق يوثّق كل استعلام وردّ خام، حتى يتحقق بنفسه أن كل نتيجة مثبتة ببيانات فعلية لا ادعاءات.

**التاريخ:** 2026-11-03 · **الهدف:** `172.18.196.1` (MikroTik RouterOS v6) · **المنفّذ:** فحص مخوَّل من جهاز مشترك على شبكة "HajWaLa Net 217" · **IP الفاحص:** 172.18.196.2

---

## 1) دليل: الواي فاي بلا تشفير

```
netsh wlan show interfaces
SSID           : HajWaLa Net 217
Authentication : Open        ← لا تشفير
Cipher         : None        ← كل البيانات مكشوفة
Signal         : 95%
```
**المعنى:** أي جهاز في نطاق التغطية يلتقط حركة كل المشتركين — كروت، تصفح، كلمات مرور صفحات HTTP.

## 2) دليل: المنافذ المكشوفة للمشتركين (مسح TCP فعلي)

```
OPEN    53    DNS         (TCP+UDP — محول تكرار مفتوح)
OPEN    80    HTTP        ← يستجيب بصفحة "RouterOS router configuration page" (WebFig)
OPEN    8291  Winbox      ← إدارة كاملة مكشوفة لأي مشترك
OPEN    8728  API         ← إدارة برمجية مكشوفة
OPEN    8729  API-SSL     ← إدارة برمجية مكشوفة
OPEN    2000  Bandwidth-test
```
مغلق (سليم): FTP 21, SSH 22, Telnet 23, HTTPS 443, SNMP 161, BGP 179, PPTP 1723, IKE 500/4500, OpenVPN 1194, UPnP 1900, WebProxy 8080.

## 3) دليل: WebFig يستجيب للمشتركين

```
$ curl http://172.18.196.1/
HTTP/1.1 200 OK
<title>RouterOS router configuration page</title>
```
**المعنى:** صفحة الدخول الإدارية معروضة لأي جهاز على الشبكة عبر HTTP غير مشفر — بيانات دخول الأدمن تُسرق نصياً عند كل استخدام.

## 4) دليل: DNS open resolver

استعلام UDP خام لـ`google.com` على `172.18.196.1:53` ← أجاب برد 196 بايت (تكرار مفعّل للشبكة الداخلية).

## 5) اختبار الاعتماد — النتيجة الفعلية (محدود وموثّق)

اختبار دخول حقيقي على منفذ **API (8728)** ببروتوكول RouterOS الأصلي — 10 تركيبات ضعيفة شائعة:

| المحاولة | الرد الخام من الراوتر |
|---|---|
| admin:admin | `!trap =message=invalid user name or password (6)` |
| admin:12345 | `invalid user name or password` |
| admin:123456 | `invalid user name or password` |
| admin:1234 | `invalid user name or password` |
| admin:admin123 | `invalid user name or password` |
| admin:password | `invalid user name or password` |
| admin:mikrotik | `invalid user name or password` |
| admin:net123 | `invalid user name or password` |
| admin:12345678 | `invalid user name or password` |
| admin:0000 | `invalid user name or password` |

**النتيجة:** الكلمة **ليست** ضمن التركيبات التافهة ← تقييم مُصحَّح: «غير مُثبَت ضعفها تجريبياً». لكن:
- المنافذ الإدارية **تستجيب وتقبل محاولات** — هجوم تخمين آلي طويل يبقى ممكناً لأي مشترك.
- حسب الإفادة الكلمة أحرف+أرقام فقط ← مساحة تخمين أصغر؛ التوصية قائمة.
- **لم تُنشأ كروت** — يتطلب اعتماداً إدارياً غير متوفر (وهذا بحد ذاته خبر جيد: لم نتمكن من تجاوز الدخول).

## 6) إثبات الواقعية المتاح الآن بدون بيانات دخول

ما تم إثباته فعلياً بالاختبار الحي: واي فاي مكشوفة، منافذ إدارية تستجيب للمشتركين، WebFig حي، DNS تكرار مفتوح. وما **لم** يُثبت: اختراق فعلي للإدارة — لأن كلمة المرور رفضت القائمة الشائعة.

**لإثبات أعمق بموافقتك** يطلب من المالك تنفيذ واحد مما يلي على جهازه:
- منحنا وصول API بمستخدم **قراءة فقط** مؤقت ← نخرج تقرير إعدادات كامل (مستخدمون/خدمات/فايروول/إصدار دقيق) + ننشئ 10 كروت تجريبية باسم `cyber_test_XX` لعرضها كدليل.
- أو ينفذ بنفسه: `/export` ويرسلنا الملف (بعد حذف السرّيات) — نحلله ونرجع تقرير الثغرات الدقيق بالإصدار.

## 6.5) جولة محاكاة المتطفل — فحوصات إضافية (2026-11-03)

نُفّذت من وضعية "متطفل على الشبكة" — استعلامات فقط، بلا تعطيل ولا لمس لبيانات عملاء:

| الفحص | النتيجة الخام | الحكم |
|---|---|---|
| SNMP `public` community (UDP 161) | `ConnectionReset` — مغلق | ✅ سليم |
| UPnP M-SEARCH (UDP 1900) | `ConnectionReset` — مغلق | ✅ سليم |
| DNS `version.bind` CHAOS | أجاب بـ`refused` (12ب) — لا تسريب إصدار | ✅ سليم |
| DHCP/NTP/L2TP/DHCPv6 UDP | لا استجابة/مرفوض | ✅ سليم |
| **DNS خارجي `8.8.8.8:53` من داخل الشبكة** | **أجاب — قناة خروج UDP/53 مفتوحة للإنترنت** | 🟠 **قناة DNS-Tunneling محتملة — يتأكد الحكم بجهاز غير مصادق** |
| اعتماد API (10 تركيبات شائعة) | كله `invalid user name or password` | ✅ رفض — لكن المنفذ يقبل المحاولات |

**خلاصة الجولة:** سطح UDP للراوتر محكم الإغلاق — وهذا يكشف إدارة واعية جزئياً. الخطر المتبقّي الحقيقي والمُثبت: (1) واي فاي بلا تشفير، (2) منافذ إدارية تخدم المشتركين، (3) قناة DNS خارجية قد تعني تجاوز هوتسبوت — الأخيرة تحتاج جهازاً غير مصادق للحسم.

## 6.6) حسم الاختبار — جهاز غير مصادق + فحص العزل (2026-11-03)

| الاختبار | الطريقة | النتيجة |
|---|---|---|
| **تصفح بدون كرت** | جهاز جديد اتصل بالواي فاي دون إدخال أي كرت ثم محاولة تصفح | **لم يدخل — لا تصفح** ✅ الجدار يمنع غير المشتركين — **لا تجاوز للهوتسبوت** |
| **عزل المشتركين** | مسح TCP(80/443) + ICMP ping + جدول ARP على كامل `172.18.196.0/24` | لا جهاز مشترك يستجيب إلا البوابة — **عزل فعّال، المتطفل لا يرى أجهزة العملاء** ✅ |
| تغيير MAC لمحاكاة متطفل | `Set-NetAdapter -MacAddress` من جهاز الفاحص | مرفوض محلياً (يحتاج Admin) — ملاحظة بيئية لا تخص الراوتر |

**الحكم النهائي على تجاوز الهوتسبوت:** غير مُثبت — الجدار صمد على جهاز غير مصادق. ملاحظة التوصية تبقى استباقية: تضييق خروج UDP/53 على غير المصادقين يغلق قناة DNS-Tunneling نظرياً قبل اختبارها ميدانياً.

## 7) التصحيحات على التقرير الرئيسي

| البند | قبل الاختبار | بعد الاختبار الفعلي |
|---|---|---|
| كلمة مرور ضعيفة | «ضعيفة حسب الإفادة» 🔴 | **«رفضت 10 تركيبات شائعة — الخطر المتبقّي: منافذ إدارية مكشوفة»** 🟠 |

> الأمانة المهنية تقتضي التصحيح: لم نخترق الراوتر — وهذا يصبّ في مصلحة الشبكة. لكن البنية (واي فاي مفتوحة + إدارة مكشوفة) تبقى الثغرة الحقيقية القاتلة: أي تسريب واحد لكلمة المرور لاحقاً يكفي للاستحواذ الكامل.

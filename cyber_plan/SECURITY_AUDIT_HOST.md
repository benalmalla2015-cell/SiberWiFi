# تقرير الفحص الأمني — شبكة المضيف (المعلا)
**التاريخ:** 2026-11-03 · **النطاق:** فحص دفاعي من داخل شبكة الواي فاي (مشترك عادي) · **الراوتر:** MikroTik RouterOS v6 · **الجهاز تحت الفحص:** البوابة `172.18.196.1`

> هدف التقرير: تحصين الشبكة قبل تجربة سايبر نت. أُجري الفحص بموافقة المالك، بأدوات سلبية/استعلامية فقط — لم يُنفَّذ أي استغلال.

## 1) النتائج الحرجة 🔴

| # | الخطورة | النتيجة | الأثر |
|---|---|---|---|
| 1 | **حرجة** | **واي فاي مفتوحة كلياً** (`Authentication: Open / Cipher: None` على SSID "HajWaLa Net 217") | كل بيانات المشتركين تمر **مكشوفة** — أي جهاز بالشارع يلتقط أرقام الكروت والجلسات والتصفح بالكامل |
| 2 | **حرجة** | **WebFig (80/HTTP) مكشوفة للمشتركين** — صفحة "RouterOS router configuration" تستجيب من الشبكة الداخلية | مع صفحة دخول على HTTP فوق واي فاي مفتوحة: اسم المستخدم/كلمة المرور تمر **نصاً واضحاً** يلتقطه أي قريب |
| 3 | **حرجة** | **Winbox (8291) + API (8728) + API-SSL (8729) مكشوفة للمشتركين** | أي مشترك يستطيع محاولة دخول إدارية للراوتر. مع كلمة مرور ضعيفة (أحرف+أرقام فقط) = استحواذ كامل على الشبكة خلال دقائق |
| 4 | **عالية** | **منافذ الإدارية تقبل محاولات دخول من المشتركين** — اختُبرت 10 تركيبات شائعة عبر API حي ورُفضت جميعها (كلمة المرور ليست تافهة — لكن حسب الإفادة أحرف+أرقام فقط، وهجوم تخمين طويل يبقى مفتوحاً) | تسريب أو تخمين كلمة واحدة = سيطرة كاملة على الشبكة، قطع الخدمة عن كل المشتركين، سرقة الكروت |
| 5 | **عالية** | **مُحوّل DNS مفتوح التكرار (Open Resolver)** — يجيب استعلامات لأي جهة داخلية | قابل لإساءة الاستخدام بهجمات تضخيم DNS، ويكشف تفاصيل الشبكة |
| 6 | **متوسطة** | **Bandwidth-server (2000) مكشوف** | معلومات/اختبارات غير مقصودة؛ يُفضّل إغلاقه أو تقييده |
| 7 | **متوسطة** | **الإصدار v6 قديم الحُكم** — لم يتسنَّ التحقق من البناء الدقيق | إن كان أقدم من 6.42.7 ← ثغرة **CVE-2018-14847** (سرقة بيانات الدخول من Winbox بدون كلمة مرور) — ترقية عاجلة |

## 2) ما هو سليم ✅ — مُثبت بالاختبار الحي

- **جدار الهوتسبوت سليم**: جهاز جديد اتصل بالواي فاي بدون كرت ← **لم يحصل على تصفح** — لا تجاوز للبوابة.
- **عزل المشتركين مفعّل**: من داخل الشبكة لا يُرى ولا يُجاب أي جهاز مشترك آخر (ping وARP فارغان) — متطفل لا يهاجم عملاءك.
- **سطح UDP مُحكم**: SNMP/UPnP/NTP/DHCP/L2TP كلها مغلقة أو صامتة؛ DNS يقبل التكرار داخلياً فقط ويرفض `version.bind` (لا تسريب معلومات).
- كلمة مرور الإدارة **رفضت 10 تركيبات ضعيفة شائعة** عبر API حي.
- منافذ Telnet(23)/FTP(21)/SSH(22)/PPTP(1723)/VPN(1194,500,4500)/BGP(179) **مغلقة** — إغلاق الخدمات القديمة ممتاز.
- MNDP لم يُلتقط خلال نافذة الاستماع — كشف الجيران مقيّد أو معطّل.

## 3) التوصيات — بأولوية التنفيذ

### فورية (هذا الأسبوع)
1. **كلمة مرور admin قوية**: ≥14 خانة، أحرف كبيرة/صغيرة + أرقام + رموز، غير مستخدمة في أي مكان — وتغيير اسم المستخدم عن `admin` أيضاً.
2. **تقييد الوصول الإداري للشبكة الداخلية فقط** (وليس شبكة المشتركين):
   ```
   /ip service set www address=<lan-admin-only>
   /ip service set winbox address=<lan-admin-only>
   /ip service set api,api-ssl address=<lan-admin-only>  أو تعطيلها إن لم تُستخدم
   /ip service set btest disabled=yes
   ```
   والأفضل: عنوان IP إداري مخصص لا يصله المشتركون.
3. **DNS**: `/ip dns set allow-remote-requests=yes` يبقى للمشتركين لكن مع قاعدة فايروول تمنع استعلامات DNS من خارج الشبكة (input udp/53 من WAN ← drop).
4. **تشفير الواي فاي**: حتى شبكة البيع تحتاج WPA2-AES بكلمة سر عامة (أو الانتقال لنموذج سايبر Enterprise الذي يشفّر لكل مشترك بشهادته — وهذا حلّنا الجاهز أصلاً).
5. **عزل المشتركين عن بعضهم**: `forwarding=no` في access-list + drop قاعدة forward داخلية — أحد المشتركين لا يرى أجهزة الآخرين (مدمج فعلياً في قالب سايبر v6).

### قريبة (خلال أسبوعين)
6. **ترقية RouterOS** إلى آخر 6.49.x كحد أدنى (يغلق CVE-2018-14847 وعائلة Winbox) — وخطط لـv7 لاحقاً للحصول على WireGuard (نفق مشفر لـRADIUS بدل الإنترنت المكشوف).
7. **نسخ احتياطي موقّت** للإعدادات (`/system backup`) + تصدير `/export` محفوظ خارج الراوتر.
8. **تعطيل UPnP** إن كان مفعّلاً (`/ip upnp set enabled=no`).
9. **فحص جدار الحماية**: تأكد من قاعدة `drop` نهائية على input للـWAN + `fasttrack` فقط للـforward.

### بنيوية
10. عند انضمام شبكة سايبر نت: الـSSID الجديد `CyberNet` يعمل على **VLAN/Bridge معزول** تماماً عن شبكته الأصلية — انطلاق أي خلل في سايبر لا يمس مبيعاته الحالية (مدمج في القالب).
11. الراوتر نفسه سيصل لسيرفرنا على UDP 1812/1813 — لا يحتاج فتح أي منفذ داخلي سوى قبول CoA (3799) من عنوان سيرفرنا فقط (موجود في القالب).

## 4) ملاحظة عن تجربة سايبر على v6

قالب المضيف الأساسي صُمم لـv7 (WireGuard). لصديقك أعددنا **`host.v6.rsc.tmpl`** — نفس العزل والمصادقة لكن بـRADIUS مباشر عبر الإنترنت مقيّد بعنوان سيرفرنا + سرّ فريد 40 حرفاً. آمن للتجربة؛ والترقية لـv7 لاحقاً تضيف النفق المشفر كاملاً.

## 5) ملخص تنفيذي لصاحب الشبكة
شبكتك **أقوى من المتوسط** — الجدار يمنع غير المشتركين، العزل يحمي العملاء من بعضهم، والكلمة صمدت أمام التخمين. لكن **أي مشترك على شبكتك يستطيع الوصول لصفحة إدارة الراوتر وسرقة كلمات المرور لأنها تمر بلا تشفير** — تسريب واحد يكفي لقلب الطاولة. ثلاثة إجراءات اليوم تُسدّ 90% من الخطر: كلمة مرور قوية + تقييد Winbox/WebFig للإدارة فقط + WPA2. وباقي القائمة تبني شبكة محترفة قادرة على النمو بأمان.

**الحكم النهائي:** شبكة جيدة البنية تحتاج غلق باب الإدارة — أنت أقرب للاحتراف من الخطر، وأولويات الإصلاح موثّقة بالأدلة في الملحق السري.
